Oct 25, 2026 · Phase 1 of the [execution roadmap](../execution-roadmap.md)

**Decision: approved.** The fork computes exactly what PyFWI 0.1.10 computes (bit for bit, on
NVIDIA and on POCL, without guard bands), installs and runs with current NumPy and SciPy on Python
3.10 to 3.13, and is faster in every scenario. Four open points, none of which blocks Phase 2, are
listed at the end.

## What Phase 1 changed and found

- **Speed without numerical change.** Kernels retrieved once with constant arguments set once (1.3),
  residual sent once per shot (1.4), contiguous checkpoints copied without blocking (1.5), an
  element-wise low-pass filter with a real FFT (1.6). Blocking copies per time step fell from 2.71 to
  below 0.01; the GPU is busy 72 to 88 % of the time instead of 28 to 51 %.
- **Robustness.** Own device selection without PyOpenCL's prompt and single-device failure (1.2);
  margins around every buffer that keep the out-of-bounds accesses of the 0.1.10 kernels inside the
  allocation (1.7); one OpenCL context per device (1.7).
- **A wrong diagnosis corrected.** Phase 0 attributed the `CL_OUT_OF_RESOURCES` crash after a few
  propagations to the out-of-bounds accesses. Step 1.7 showed it is caused by releasing an OpenCL
  context while another exists on the same NVIDIA device; the guard bands of the tests had hidden it
  by keeping every context alive.
- **NVIDIA driver behaviours to remember for the CUDA backend.** An allocation created with
  `COPY_HOST_PTR` is placed on the device only for the sub-buffer region the kernels use; overlapping
  sub-buffers crash the driver when released.
- **Packaging.** Distribution `pyfwi-cuda` (import name `PyFWI`), real dependencies, extras `segy` and
  `torch`, `PyFWI.info()` for bug reports (1.8).

## Open points

1. **Self-hosted GPU runner** not registered (owner action, unchanged since G0). Every commit of Phase
   1 ran the fast suite on NVIDIA and on POCL, the reference suite and the slow suite on the RTX before
   being pushed. How to register it: [self-hosted-runner.md](../self-hosted-runner.md).
2. **Nsight Compute** still cannot read the GPU counters (owner action, roadmap pending action 1).
   Needed from Phase 2 on to measure the bandwidth of the CUDA kernels.
3. **CPU CI on some GitHub runners.** PoCL 3.0 (the newest on PyPI) cannot compile for the AMD EPYC
   9V45 (Zen 5) of some runners; there the OpenCL tests are reported as skipped with a warning
   (`5a791f9`). A newer PoCL from conda-forge would remove it; to be decided when POCL comparisons
   become a CI requirement.
4. **Review of the FWI results by a geophysicist** (catalogue, test FWI): the inversions are those of
   0.1.10 bit for bit, so nothing changed to review; it becomes necessary with the `fixed` mode.
