# Parity of the CUDA backend with OpenCL (release 0.3.0)

CUDA against OpenCL on the same GPU, on the whole matrix of the golden masters (`tools/parity_report.py`): relative L2 difference `||cuda - opencl|| / ||opencl||` of every output, in each numeric mode, each backend with its default settings. In the `legacy` mode both backends run the same kernel files; in the `fixed` mode the CUDA backend runs, since 0.3.0, the native kernels of Phase 3, which compute the same thing with some operations in another order (multiplications by 1 / dx instead of divisions, the shots in batches whose gradients are added at the end). The compilers also emit different instructions (contractions into fused multiply-adds), hence differences of the order of rounding, checked by the tolerances of `test/test_parity.py`.

The largest gradient differences, in the `fixed` mode, are those of one case (wells and surface, pressure data, energy balancing), whose gradient is the most sensitive to rounding: in 0.2.0, compiling the CUDA kernels without contraction into fused multiply-adds alone changed it by 7e-4, and NVIDIA OpenCL and POCL (OpenCL on the CPU) differ by 3e-5 there. The `legacy` mode differs less because its double-precision constants make part of its arithmetic FP64.
